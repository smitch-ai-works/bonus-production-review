# いそっち式 AIコンビ連携マニュアル｜16:9解説動画

撮影待ち。以下は話すセリフ全文と対応する画面操作。仮尺は約7〜9分。実行待ちの時間を除く原稿量からの目安で、収録済みの尺ではない。

## 撮影準備

- 16:9、1920×1080を基本に、ブラウザとClaude Codeの文字が読める倍率で収録する。個人の会話、アカウント、通知、認証情報を映さない。
- 特典のindex.htmlと、新しい練習フォルダを用意する。既存の本番プロジェクトを使わない。
- ZIPを展開し、practiceのbrief.mdを新しい練習フォルダへコピーする。posts-before.md等は参考用なので、初回実演の入力には置かない。
- Claude Codeと公式Codexプラグインを用意する。既に導入・認証済みなら設定をやり直さず、その状態を説明する。未導入・未認証なら本人が事前に公式の導入と認証を完了する。
- 顔カメラは冒頭と最後を中心に出し、操作中は入力位置と結果を大きく見せる。待ち時間は編集でカット可能。パスは撮影用フォルダだけを表示する。

## 1. 表紙→困りごと→今回できること

【画面】表紙を表示。次に動画枠の下の「AIを行き来して、手が止まってませんか？」までスクロール。本人カメラあり。

【セリフ】

「いそっちです。今回は『いそっち式 AIコンビ連携マニュアル』を、実際に使っていきます。

AIに頼みたいけど、何を渡せばいいか迷う。修正のたびに、別のAIに貼り直してる。出てきた答えを、誰に確認させるかも決まってない。こういうところで手が止まってませんか？

今回作るのは、Claude CodeとCodexの役割分担です。Claude Codeが全体の設計と最終確認。実際にファイルを作ったり直したりするのはCodex。依頼から確認までを、一つの流れにつなぎます。

僕はこれでAI社員を作って動かしてる。別々に使うより、役割を決めてつなぐのがいいんです。

いきなり大きな仕事じゃなくて、まずは小さい仕事を一つ。今日は、架空のカフェの投稿文を3案作って、1箇所直して、保存するところまでやってみます。」

## 2. 先に完成例を見る

【画面】「まず、この流れを作る」を指し示す。次に04の結果画像、投稿3案の詳細を開く。修正前後の案1の最後の一文を拡大。

【セリフ】

「流れはこれです。Claude Codeが条件を決める。Codexが投稿を作る。Claude Codeが元の情報と見比べる。直したいところをCodexに返して、修正後をもう一度確認します。

完成すると、投稿文がファイルになります。こちらが今回の練習結果。最初は『本を読むひとときを、コーヒーと一緒に。』という締めでした。ここだけを『お店でお待ちしています。』に変えています。

店名と営業時間、予約不要という情報はそのままです。案2と案3も変えていません。こういうふうに、条件と直す場所をはっきりさせて受け渡します。」

## 3. Codexを追加する

【画面】特典の01を開く。3つのコマンドを上から1つずつコピーしてClaude Codeの入力欄へ。導入済み環境では実行を省略し、コマンドと候補表示だけを示す。

【セリフ】

「設定はPCのClaude Codeで進めます。使うのは、OpenAIの公式Codexプラグインです。

初めて入れる人は、ここを上から一つずつ送信してください。まずマーケットプレイスを追加。次にCodexプラグインをインストール。最後にプラグインを読み直します。

僕の撮影環境では、ここは導入済みです。導入済みの人は重ねて入れなくて大丈夫です。

入力欄で『/codex』と打って、setupやrescueなどの候補が見えるか確認します。出なければセッションを開き直し、プラグインが有効かを見てください。詳しい準備は、この開く欄と公式手順にまとめてあります。」

【撮影メモ】実際の撮影環境が未導入の場合は「僕の撮影環境では〜」の2文を読まず、本人が実際に行った導入を見せる。確認ダイアログは内容を読み、許可対象を確かめる。見えていない成功画面を編集で作らない。

## 4. 認証状態を確認する

【画面】02の/codex:setupをコピーして実行。認証済みと分かる箇所だけを映す。個人のID等は収録範囲から外す。未認証の説明は特典内の補足を表示し、ログイン画面や認証コードは収録しない。

【セリフ】

「次は、使える状態かの確認です。『/codex:setup』を送ります。すでに認証できていれば、そのまま次へ進めます。

未認証なら『!codex login』を送ると、ChatGPTのアカウントでサインインする流れになります。ブラウザで使いたいアカウントを確認して、ログインしてください。認証情報をAIのチャットへ貼る必要はありません。

モデル名は、そのときの利用環境で選べるものを使ってください。今回の役割分担は、名前を固定する設定ではありません。

あと、分担すれば必ず使用量が減る、ということではないです。確認を何度も回せば、その分の利用枠は使います。最初は、作業を見ながら一件だけ試すのがいいです。」

## 5. 役割分担を練習フォルダへ残す

【画面】新しい練習フォルダを開く。03の「役割分担の指示文を開く」→「全文をコピー」→Claude Codeへ貼り付けて送信。保存後のCLAUDE.mdを開く。

【セリフ】

「ここからは、新しい練習フォルダでやります。既に動いている本番のフォルダじゃなくて、練習用を一つ作ってください。

この指示文を送ります。Claude Codeは設計と確認。Codexは作成と修正。何を作るか、どこへ保存するか、何ができれば終わりかを先にそろえます。

元ファイルを残すことと、同じファイルを同時に触らないことも入れてあります。確認して、直す場所を具体的に返す。ここまでを一つの役割分担にしています。

保存したCLAUDE.mdを一度開いて、この分担が入っているかを見ます。次も同じフォルダを開けば、そのフォルダのルールとして読める形です。ほかのフォルダまで勝手に変える設定ではありません。

既存のCLAUDE.mdがある人は、丸ごと置き換えずに差分を見てください。」

【確認】ファイル保存が実際にできたこと、指定した役割と制限が残っていることを画面で確認してから次へ進む。失敗した場合は成功と読まず、その操作を撮り直す。

## 6. 同じ投稿を作成・変更・確認する

【画面】ZIPを保存して展開。「ガイド.html」を開き、practice/brief.mdを新しい練習フォルダに配置。brief.mdを開く。04の実演指示文を全文コピーして送信。処理待ちはカット。

【セリフ】

「練習ファイルも入れてあります。ZIPを展開すると、このガイドとpracticeフォルダが出てきます。今回入力に使うのはbrief.mdだけです。

架空の『こもれびカフェ』。営業時間は10時から18時。コーヒーを飲みながら読書できる。予約は不要。使う事実はこれだけです。

下の実演指示文を送ります。まずClaude Codeが条件を整理して、Codexに投稿3案の作成を任せます。価格や駅からの距離、限定企画や売上は、ここにないので足しません。

作成が終わったら、Claude Codeが元情報と照合します。次に、案1の最後の一文だけを『お店でお待ちしています。』へ変えるよう、同じCodexの作業文脈へ返します。

最初からこちらで全部書き直すのではなくて、直す場所を一つ決めて戻す。これをやってみます。」

【画面】実際に作成されたposts-before.mdとposts-after.mdを並べる。最後の一文だけを強調。check.mdを開く。

【セリフ】

「できたら、この3つを見ます。投稿3案がファイルになっているか。元の店名や営業時間が残っているか。そして、指定した一文だけが変わっているか。

修正前と修正後を残しているので、何を直したかも見比べられます。最後にcheck.mdで、Claude Codeの確認内容も読みます。

ここがそろえば、今回の練習は完了です。もし途中で実行できないと言われたら、その箇所で止めてください。動いていないのに、完成とみなさなくて大丈夫です。」

【撮影メモ】この回の実出力が掲載作例と異なる場合、掲載文をAIが出したように語らない。撮影時の実出力をそのまま見せ、元情報と指定の差分で確認する。過去の実演画像を現在の処理結果として差し込まない。

## 動画受領後の組込み

サムネイル直下、index.htmlの`#explainer-video`が差替え箇所。受領するものは16:9のMP4（H.264映像・AAC音声を推奨）、または閲覧可能で埋込み許可のある動画URL。

ローカルMP4なら、受領許可範囲でassets/explainer.mp4へ置き、現在の案内枠を次へ差し替える。未受領の現時点では、このファイル参照をLPへ入れない。

```html
<video id="explainer-video" controls playsinline preload="metadata" src="assets/explainer.mp4"></video>
```

「解説動画」見出しは残し、受領待ちの文を外す。スマホとPCで映像・音声・再生・シーク・終端を確認する。保存用ZIPのガイドも同じ版へ更新してから再検品する。クラウド公開・配布開始は、このローカル制作とは別の操作。

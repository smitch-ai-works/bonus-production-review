3AIの役割を決める

役割分担の指示文を開く
この作業フォルダでは、Claude CodeとCodex CLIを次の役割で使います。

Claude Code：目的の整理、全体の設計、作業指示の作成、根拠との照合、最終確認。
Codex CLI：決めた設計に沿った下書き・ファイル作成・指摘箇所の修正。

この役割を、このプロジェクトのCLAUDE.mdへ保存してください。既存ファイルがあれば読み、既存の指示を保って必要部分だけ追記してください。グローバル設定は変えないでください。保存先と追記した内容を最後に示してください。

作業はこのフォルダ内に限定し、認証情報を指示ファイルへ書かないでください。Codexを呼ぶ前に、codex --versionとcodex login statusで利用可否を確認してください。未導入・未ログインなら、公式手順と必要な本人操作を示して止まってください。インストールやログインを勝手に行わないでください。

Codexへはcodex execを使い、ファイル作成が必要なときは--sandbox workspace-writeを指定してください。この練習フォルダがGit管理外の場合だけ--skip-git-repo-checkを使ってください。権限エラーを避けるためにサンドボックスを解除しないでください。

Codexへの依頼はtask.mdへ、作業結果はdraft.mdへ保存。Claude Codeはsource.txtとplan.mdを照合し、問題のある行と修正指示をreview.mdへ記録。指摘があればCodexへ差分だけ戻してください。修正は最大2回を目安にし、残る問題は黙って承認せず示してください。最終稿はposts.mdへ保存します。

外部送信、投稿、公開、購入、設定変更は行わず、ローカルのファイル作成まで進めてください。

次のセッションでも同じ役割を使うために、このフォルダのCLAUDE.mdへ保存します。チャットで一度伝えただけで、ずっと記憶されるという意味ではありません。

4投稿3本の作成を渡す

同じ商品紹介を3本作るより、伝える役割を先に分けます。今回は商品・過ごし方・来店前。この設計を、Codexへ渡します。

投稿3本を作る指示文を開く
source.txtを読み、Instagram本文3本を完成させてください。

まずClaude Codeでplan.mdを作り、①チーズケーキの紹介 ②窓際の一人用席 ③営業時間と定休日、の役割を決めてください。目的は「商品の特徴と来店前の情報を伝える」です。

次にCodexへ渡すtask.mdを作成し、source.txt・plan.mdを読むよう指示してください。各投稿は見出しと80〜140字を目安とした本文に分け、draft.mdへ保存させてください。実際の字数も確認してください。

Codexを呼ぶコマンド例：
codex exec --skip-git-repo-check --sandbox workspace-write -o codex-result.txt "task.mdを読み、source.txtとplan.mdの条件でdraft.mdを作成してください。原資料にない事実を足さず、このフォルダ内の作業だけを行ってください。"
※Git管理下なら--skip-git-repo-checkは外してください。

Codexが終了したら、Claude Codeでdraft.mdを実際に開き、source.txtとの矛盾・未記載の事実・3本の役割の重複・字数を確認してください。問題があればreview.mdへ具体的な修正指示を保存し、Codexへ修正箇所だけ戻してください。修正後の実ファイルを再び照合し、問題が解消したものをposts.mdに保存してください。最大2回で解消しない点は一覧にして止めてください。

最後に、作成したファイル・直した箇所・残る確認事項を報告してください。公開や投稿は不要です。
Claude CodeからCodexを呼ぶコマンド

上の指示文には、次の呼び出しも入っています。Claude Codeがpractice内で実行する想定です。

codex exec --skip-git-repo-check --sandbox workspace-write -o codex-result.txt "task.mdを読み、source.txtとplan.mdの条件でdraft.mdを作成してください。原資料にない事実を足さず、このフォルダ内の作業だけを行ってください。"

--sandbox workspace-writeは作業フォルダ内の編集用。-oは最後の報告の保存先です。--skip-git-repo-checkは、今回のようなGit管理外の練習フォルダだけで使います。Git管理下では外します。

呼び出しが止まったら、エラーとcodex --versionを確認してください。OpenAI公式：codex exec ／ コマンドとオプション

この役割分担は、モデルの優劣を固定するものではありません。使えるモデルは各アカウントで確認してください。処理量や利用枠は仕事の内容で変わります。

5出てきた文章を、もう一方が確認する

結果を確認する指示文を開く
draft.mdとsource.txtを行ごとに照合してください。
1. 原資料にない人気・順位・住所・口コミ・効果・予約方法を足していないか。
2. 価格650円/500円、10:00〜18:00、火曜定休を取り違えていないか。
3. 3本が商品・過ごし方・来店前情報に分かれているか。
4. 見出しを除いた各本文が80〜140字の目安に収まるか。句読点・記号も1字、改行は除外して数える。
問題がある行と、source.txtの根拠をreview.mdへ記録してください。
Codexへは修正点だけを渡し、直した実ファイルを読み直してください。修正を確認してからposts.mdへ保存してください。判断できない事実は作らず、本人確認が必要な項目として残してください。

直すたびに全部を説明し直す必要はありません。問題のある一文と、直す条件を戻します。修正の往復が増えすぎたら、いったん残る問題を確認しましょう。

利用量を抑えながら回すには

渡すファイルと完成条件を絞り、修正時は指摘箇所だけ戻します。2つのAIを使えば必ずトークンが減るわけではありません。今回の指示文は修正を最大2回の目安にして、終わらない往復を避けています。必要な回数は仕事に合わせて変えてください。

6最終稿を保存する

✓ 3本それぞれの役割が違う
✓ 価格・営業時間・定休日が原資料と一致
✓ 人気・口コミなど、不明な事実を足していない

最後はposts.mdを自分でも開いて確認。まずはこの3本で、AI同士に作業を渡して戻す感覚をつかんでみてください。

自分の仕事へ変えるときの書き換え方

source.txt：自分が使ってよい原稿・商品の事実を入れる。
目的：誰へ何を伝えるかを1つにする。
出力：投稿3本、記事1本など完成物と保存名を決める。
確認：数字・固有名詞・引用・禁止表現など、照合する条件を指定する。

いきなり仕事を全部渡さず、まずは一つの成果物から。AI社員は人間の社員という意味ではなく、このように役割を持たせたAIの使い方です。

# 構成先行式 AI note実践ガイド

会議後のメモを、担当・期限が分かる依頼文へ変える。その方法を伝える有料noteの原稿を、一つの題材で最後まで作るガイドです。

いきなり本文を書かせず、材料と見出しを先に決めます。最後に口語へ直すときも、担当・期限などの条件は変えません。AIには整理と下書きを任せ、何を残すか、何が事実かは自分で確認します。

この教材の会社員・経歴・回答・会議メモは、すべて説明用の架空例です。すみっち本人の実体験・販売実績ではありません。

## 最初に開くもの

- このファイル：5工程の実践例。構成を直した理由まで確認できます。
- `02_コピープロンプト.txt`：各工程で使う指示文。自分の材料に差し替えられます。
- `03_完成記事見本.md`：無料部分と有料部分の境界を含む完成原稿。
- `04_自分用ワークシート.md`：自分の材料と判断を保存する空欄シート。

手元のテキストエディターで開けます。Markdown対応のエディターでは見出しや表を整えて表示できます。

## 通して使う作例

想定読者は、会議に参加したあと、同僚への依頼を文章にするときに迷う会社員。渡す価値は、会議メモから「担当・作業・期限」を取り出し、未定の条件を勝手に埋めずに依頼文へ変える手順とテンプレートです。

```text
11/11 企画定例
A社向け次回提案の準備
・田中：A社の要望を3点に整理。11/12 15時まで。
  共有フォルダに保存し、リンクをチャットに返信。
・佐藤：提案書のたたき台。期限は未定。
・金額：部長確認待ち。
・次回会議：11/14 10時。
```

完成する依頼文の一例：

> 田中さん、A社の要望を3点に整理して、11月12日15時までに共有フォルダへの保存をお願いします。保存後、リンクをこのチャットに送ってください。

期限がない佐藤さんの依頼は、同じ締め切りを流用しません。「提案書のたたき台の期限を確認したいです。いつまでに用意できそうか、教えていただけますか」と確認します。

## ① 同じ読者のnoteを5本選ぶ

本番では、発信する分野のnoteを探し、無料で読める範囲を5本集めます。「売れている」は売上が確認できる場合にだけ書きます。スキ数やタイトルだけで販売実績は判断できません。記録するのは、記事名・URL・確認日・選んだ理由・確認できた事実です。

この教材では実在noteの本文を収集していません。下の5本は構造を練習するために作った仮データです。人気や売上を示す資料としては使いません。

### 構造の整理例：5本の無料部分に相当する仮データ

| 例 | 仮のタイトル | 仮の冒頭 | 無料部分に置く見出し |
|---|---|---|---|
| A | 会議メモから依頼文へ。誰が・何を・いつまでにを分ける | 会議の内容は残っているのに、次の依頼文が書けない。そのときは文章を磨く前に、決まった条件を分けます。 | 決まったことを拾う／3列に分ける／依頼文にする |
| B | 「確認お願いします」で止めない、会議後チャットの作り方 | 何を確認してほしいのかが抜けると、相手は返し方に迷います。確認してほしい点を一つ選ぶところから始めます。 | 相手にしてほしいこと／確認の範囲／返信の形 |
| C | 期限がない会議メモは、埋めるより先に聞く | 会議メモに締め切りがなければ、次の会議日を勝手に入れない。未定を見つけることも、整理の仕事です。 | 決定と未定を分ける／未定の書き方／期限を尋ねる文 |
| D | メモをそのまま送らない。担当別に分ける依頼テンプレート | 全員の作業が並ぶメモと、一人に送る依頼では必要な情報が違います。相手に関係する行だけを取り出します。 | 担当別に切り出す／作業と保存先／送信前の照合 |
| E | 硬い依頼文を短くする、会議後メッセージの直し方 | 丁寧に書いたつもりで、何を頼むかが後ろへ回っていないか。宛先、作業、期限を残して、遠回りな言い方を減らします。 | 条件を固定する／表現を短くする／直す前後を比べる |

## ② 無料部分を、理由・タイトル・冒頭・見出しに分ける

`02_コピープロンプト.txt` の「② 無料部分の分析」を使います。参考の文章そのものを再利用するためではなく、情報を出す順番を見つけるための工程です。

| 例 | 読まれる理由として考えられる点（仮説） | タイトルの働き | 冒頭の働き | 見出しの流れ |
|---|---|---|---|---|
| A | 一つの場面と完成物が想像しやすい | 会議メモ→依頼文の変化を示す | メモはあるのに書けない状況を置く | 抽出→整理→文章 |
| B | 曖昧な依頼を具体的に直せる | よく使う言葉を入口にする | 相手が迷う理由を示す | 行動→範囲→返信 |
| C | 決まっていない情報の扱いが分かる | やってしまいがちな補完を止める | 次回会議日と締め切りを区別する | 決定→未定→確認 |
| D | 誰に何を送るかを分けられる | メモと依頼文の役割差を示す | 全員向けの記録を一人向けに変える | 切り出し→条件→照合 |
| E | 条件を保った文章修正が見える | 修正対象と用途を限定する | 長い丁寧表現に埋もれる依頼を示す | 固定→修正→比較 |

本番でも、無料部分から有料部分の内容や売上は推測で埋めません。売れている理由を問う場合は、売上の事実と、文章から考えた仮説を分けます。

今回採る型は「困る場面→完成例→手順→未定の扱い→照合→テンプレート」。Aの操作順、Cの未定の扱い、Dの照合、Eの比較を参考にします。タイトルの言い回しや冒頭の文章は写しません。

## ③ 10個の質問に答え、記事に使える強みを3つ選ぶ

以下は、架空の会社員が答えた説明用の回答です。自分用に進めるときは、実際の経歴・行動・説明できる範囲だけを書きます。「特にない」「未経験」も回答です。

| 質問 | 架空の回答 |
|---|---|
| 1. どんな仕事・役割をしていますか？ | 営業事務として、会議後の連絡や資料のとりまとめを担当する設定です。 |
| 2. 人からよく頼まれる作業は何ですか？ | 箇条書きのメモを、担当別の連絡に分ける作業です。 |
| 3. 作業の途中で、何を必ず確かめますか？ | 誰の作業か、何を仕上げるか、期限が決まっているかを確かめます。 |
| 4. 自分なりの整理の仕方はありますか？ | 文章にする前に「担当・作業・期限」の3列に分けます。 |
| 5. 初めて行う人が迷いそうな点は何ですか？ | 次の会議日を作業の締め切りだと思い込むことです。 |
| 6. 一つだけ説明するなら、何を教えられますか？ | 会議メモから一人分の依頼文を作る手順です。 |
| 7. どんな場合は言い切らずに確認しますか？ | 担当や期限、金額が決まっていない場合です。 |
| 8. 記事に書けないこと・未確認のことは何ですか？ | 売上、作業時間の削減率、相手の反応など、実測していない結果です。 |
| 9. 誰のどんな場面に絞ると説明しやすいですか？ | 会議のあと、同僚へのチャットを書こうとしている人です。 |
| 10. 文章の雰囲気を示す短い言い方を3つ挙げると？ | 「まず、ここだけ。」「たとえば、こんな感じです。」「迷ったら、確認です。」という仮の口調にします。 |

### 回答から選んだ3つの強み

1. **連絡の直前まで具体化できる。** 回答2・6・9から、一般的な議事録術ではなく、一人に送る依頼文へ絞ります。完成例とテンプレートを記事に入れます。
2. **担当・作業・期限を分けて説明できる。** 回答3・4から、3列整理を中心手順にします。抽象的な効率化論より先に、元メモと表を見せます。
3. **未定を未定のまま扱う。** 回答5・7・8から、勝手な補完を避ける判断を入れます。期限未定の佐藤さんへの文を、田中さんへの確定した依頼と分けます。

これは架空回答からの記事の切り口です。特別な才能や優れた実績の証明ではありません。自分用では、答えに根拠がない強みは採用せず、追加で聞いてもらいます。

## ④ 見出し10個を決めてから、本文を書く

いきなり本文を作ると、似た説明が重なっても長文の中で気づきにくくなります。まず見出しだけを比べ、読者が使う順番になっているかを見ます。

### 構成の修正前→修正後

| 修正前：広く、重複がある構成 | 修正後：今回採る10見出し |
|---|---|
| 1. 会議メモの大切さ | 1. 会議メモは「記録」と「依頼」を分ける |
| 2. 情報整理の重要性 | 2. この見本で作る依頼文 |
| 3. 仕事を効率化する考え方 | 3. メモから決定事項だけを拾う |
| 4. 誰に頼むか | 4. 担当・作業・期限の3列に分ける |
| 5. 何を頼むか | 5. 決まっていない欄は「要確認」にする |
| 6. 依頼の仕方 | 6. 依頼文を「宛先→作業→期限」の順に組む |
| 7. 伝わる文章 | 7. 返信が必要な点を一つに絞る |
| 8. 期限について | 8. 硬い表現を、条件を変えずに短くする |
| 9. 相手に伝える工夫 | 9. 送る前にメモと照合する |
| 10. まとめ | 10. 自分の会議で使う空欄テンプレート |

修正前の1・2は前置きが重複し、6・7・9は何をする章か曖昧です。期限の確認も文章を組む前に必要です。そこで完成例を先に置き、抽出→3列→未定の確認→依頼文→照合の順へ直しました。「まとめ」は、読者が持ち帰れる空欄テンプレートへ変えています。

### 無料部分と有料部分の境界

この原稿見本では、1・2を無料部分、3〜10を有料部分の想定にしています。無料部分では困る場面と完成物を見せ、有料部分では再現する手順・未定の扱い・テンプレートを渡します。実際の価格や販売設定を決めたものではありません。

採った10見出しと材料をそろえてから、`02_コピープロンプト.txt` の「④-B 本文」を使います。完成原稿は `03_完成記事見本.md`。この作例ではすみっち本人や架空著者の体験談を加えず、手順と具体例で本文を成立させています。

## ⑤ AIらしい言い方を直し、条件を照合する

ここで変えるのは話し方です。期限、担当、作業、保存先を変える工程ではありません。口癖を増やしすぎず、3つを自然な場所へ一度ずつ置きます。

### 同じ条件のまま、文章だけを直す例

**修正前**

> それでは、担当者・作業内容・期限を明確にしましょう。田中さんには、A社の要望を3点に整理し、11月12日15時までに共有フォルダへ保存していただきます。保存後は、リンクをチャットに返信していただくことが重要です。佐藤さんの提案書のたたき台の期限は未定のため、確認する必要があります。

**修正後**

> たとえば、こんな感じです。田中さんには「A社の要望を3点に整理して、11月12日15時までに共有フォルダへの保存をお願いします。保存後、リンクをこのチャットに送ってください」と頼みます。佐藤さんの提案書のたたき台は期限が未定なので、先に確認します。

「明確にしましょう」「重要です」を、相手に送る具体的な文へ変えました。田中さん・要望3点・11月12日15時・共有フォルダ・リンク返信、佐藤さんの期限未定という条件は同じです。架空の成功談や数字は足していません。

### 最後に読むチェック

- 誰のどんな場面かが、タイトルと本文でそろっている。
- 10見出しの重複が減り、使う順番になっている。
- 未定の担当・期限・金額を、AIが勝手に決めていない。
- 仮データを実在の人気記事・販売実績として書いていない。
- 口語修正で、元メモの条件や記事の約束が変わっていない。
- 無料部分で見せた完成物を、有料部分の手順で作れる。

## 保存して、自分の1本に変える

1. 配布ページのZIPを保存して展開し、4つの教材ファイルを同じフォルダで開きます。
2. `04_自分用ワークシート.md` を複製し、作りたい題材の名前を付けます。
3. 参考5本の記録、10回答、強み3つ、採った見出し10個を順に入れます。
4. AIの本文案を別名で保存し、口語へ直した最終版も残します。例：`自分の題材_本文案.md`、`自分の題材_最終原稿.md`。
5. テキストエディターで「名前を付けて保存」を選び、文字コードをUTF-8にします。保存後に閉じて開き直し、日本語、見出し、無料・有料の境界が読めるか確認します。

noteに移す場合は、最終原稿のタイトルと本文を新規下書きへ入れ、見出し・表・引用をプレビューで整えます。この教材の境界表示は原稿上の目印です。販売価格、実際の有料境界、公開の設定は、掲載時の画面で自分で確認します。

最初の一手は、完成記事をそのまま自分の実話にすることではありません。ワークシートの「誰の、どの場面か」を、自分が説明できる題材で1行書くところから始めてください。

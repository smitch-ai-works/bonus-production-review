# 見出し先行式 AI note制作ガイド｜Codexで進める

参考5本の分析、強みの整理、構成案、本文、口語への修正を、同じフォルダへ順番に残します。10問への回答と構成の採用は自分で行います。**いきなり本文に進めず、構成を決めてから書く**ための進め方です。

すでにCodexでローカルファイルを扱える方向けです。APIキー、プログラム、新しいスキルのインストールは使いません。利用できる機能や画面は、アカウントと環境によって異なります。

## 1. このフォルダを作業場所にする

1. 配布ファイルを展開し、`codex-workflow`フォルダを手元へ保存します。1記事ごとにこのフォルダをコピーすると混ざりません。
2. `input.md`をテキストエディタで開き、「記事の条件」と「参考5本」を入力して保存します。「質問への回答」「構成の採用」は最初は空欄で大丈夫です。
3. Codexで、このフォルダを使うローカルのプロジェクト／作業場所を開きます。デスクトップ版で選択肢がある場合は、Codexを選び、`This computer`／`Local`など自分のコンピュータで動く方を使います。プロジェクトのフォルダを追加する画面では、このフォルダだけを指定します。[公式：プロジェクト](https://learn.chatgpt.com/docs/projects)、[公式：実行場所](https://learn.chatgpt.com/docs/environments/modes)
4. 選択した作業フォルダが`codex-workflow`になっていることを確認し、次の依頼文をチャットへ貼ります。

```text
このフォルダのTASK.mdを全文読み、input.mdを材料にnote記事を1本作ってください。
このフォルダ内だけを作業範囲にし、各段階をresults/へ保存してください。
まず参考5本の無料公開部分を分析し、私の経歴や得意なことを引き出す10問を出してください。
10問への回答がそろう前と、私が構成を選ぶ前には、本文へ進まないでください。
公開や外部への送信は行わず、記事本文と変更記録をファイルで渡してください。
```

`TASK.md`はAIに読ませる作業指示、`input.md`はあなたが書き換える材料です。ファイルを保存しただけでは記事は作られません。チャットから依頼して開始します。

## 2. 参考5本を渡す

発信したい分野で、同じような読者・困りごとを扱うnoteを5本選びます。有料noteを参考にする場合も、**購入なしで読める無料公開部分だけ**を`input.md`へ貼ります。URL、確認日、無料で読めた範囲も記録します。

タイトルだけ、URLだけでは分析材料が足りない場合があります。本文が取得できない環境でも進められるよう、自分で見られた無料部分を渡してください。有料部分の入手やログイン操作はこのワークフローに任せません。

売上が分からなければ「不明」のまま。価格やスキ数だけで売れた本数・売上を推定しません。AIには「売れている証拠」と「購入につながりそうな見せ方の仮説」を分けて書かせます。参考から借りるのは、悩みの絞り方や説明の順番。独特の言い回しや本文を自分の記事へ移しません。

## 3. 10問に答える

AIが`02-questions.md`を保存したら、Q1〜Q10に答えます。チャットに番号を付けて返すか、`input.md`の回答欄へ保存し「回答欄を読み直して」と伝えます。「経験なし」「分からない」「その話は使わない」も回答です。空欄は回答待ちとして扱います。

口癖は、普段使うものを3つ。そのまま入れても不自然にならない短い言葉を渡します。AIがあなたの経歴や成果を作って埋めることはしません。

回答後は、根拠付きの強み3つと見出し候補10個が出ます。ここでも本文はまだ書きません。

## 4. 見出しと順番を選ぶ

`04-outline-candidates.md`を開き、記事に使う見出しを選び、順番や表現を直します。例えば、次のようにチャットへ返します。IDは実際の候補に合わせて変えてください。

```text
採用構成：H01 → H02 → H04 → H03 → H05 → H06 → H07 → H08 → H09 → H10
H03は「会議メモから担当・期限・成果物を拾う」に変えてください。
採用タイトルは、提案されたタイトルを使います。
有料部分の開始：H04の直前。
この構成で本文へ進めてください。
```

採用・不採用が分かり、必要な内容がそろっていれば、10個すべてを使う必要はありません。重複や抜けがあれば、AIが理由と修正案を示します。意味の違う構成に勝手に変えず、決まった構成を`05-outline-selected.md`へ残します。

## 5. 本文と修正記録を開く

構成を決めると、本文の下書き、口語への修正、口癖3つの反映まで進みます。`07-note-final.md`がnoteへ移す記事本文、`08-change-log.md`が修正前後と理由です。

| 保存ファイル（`results/run-001/`内） | 確かめること |
|---|---|
| `01-reference-analysis.md` | 無料範囲だけの分析か。売上不明を埋めていないか |
| `02-questions.md`・`02-answers.md` | 10問と自分の回答が対応しているか |
| `03-strengths.md` | 強み3つの根拠が、自分の回答にあるか |
| `04-outline-candidates.md` | 見出し10個の重複や抜けがないか |
| `05-outline-selected.md` | 自分が選んだ構成と一致するか |
| `06-note-draft.md` | 採用構成に沿った本文になっているか |
| `07-note-final.md`・`08-change-log.md` | 事実を変えずに自分の口調へ直したか |
| `09-publish-checklist.md` | noteへ移す前に自分が確認する項目 |
| `STATUS.md` | どこまで進み、何の回答待ちか |

2回目以降の新規作成では`run-002`のように別フォルダへ保存します。やり直し前のファイルも残します。

「〜しましょう」をすべて消すだけでは、自分の文章にはなりません。体験していない話が増えていないか、言い切りが強すぎないか、自分ならその言葉を使うかを読んで確かめてください。口癖3つも、不自然なら場所を変えるか自分で直します。

## 作例で選び方をつかむ

説明用の題材は「会議後のメモを、担当・期限が分かる依頼文へ変える」。架空の会社員を想定した例です。

- 広すぎる題材：「AIで仕事を効率化する」
- 今回の題材：「会議メモから、担当・期限・成果物を拾って依頼文を作る」
- 構成で先に決めること：「決定事項を拾う→担当・作業・期限の3列→未定を確認→依頼文→元メモと照合」の順番。匿名化は入力前に済ませます
- 本文で示す変化：メモ「田中さん／11月12日15時まで／顧客要望3点／共有フォルダへ保存、リンク返信」→「田中さん、11月12日15時までに顧客要望3点を共有フォルダへ保存し、リンクを返信してください」。一方、「佐藤さん／提案書のたたき台／期限未定」は依頼文を確定せず、期限を確かめる確認文へ分けます。人物・日時はすべて説明用の架空例です。

自分の記事では、自分が確かめられる題材と経験へ置き換えてください。会社のメモは匿名化し、共有してよい情報だけを入力します。

## 再開する・修正する

途中で止まったら、同じフォルダを開いて次のように依頼します。

```text
TASK.mdと、results内の最新実行フォルダのSTATUS.mdを読んで再開してください。
完了した工程は保持し、待っている質問・構成選択があれば、それを先に示してください。
チャット履歴だけを根拠に完了扱いにしないでください。
```

修正は「H04だけ、実際に答えた経験に合わせて直して」など対象と理由を伝えます。本文の事実や構成が変わる修正では、その変更も記録させます。

## noteへ移す

`07-note-final.md`を開いて確認し、自分でnoteのエディタへ移します。見出し、無料／有料の境界、実際に渡す内容、価格、参考・引用、公開可否を人が決めます。このフォルダはnoteへの投稿、販売設定、公開を自動実行しません。売上や完成時間も保証しません。
